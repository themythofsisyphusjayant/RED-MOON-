# Qasida dynamic registry — deploy

This is a dynamic registry: clients publish with POST, not git push.
It is a single Python file with no dependencies
(`forge_lang/registry_server.py`).

The server reads its settings from the environment, so no secret
lives in a command line: `PORT` (default 8765) and
`FORGE_REGISTRY_TOKEN` (if unset, the registry is open and
anyone can publish; if set, publishing requires
`Authorization: Bearer <token>`). CLI flags `--port` / `--token`
still override the environment. `GET /` and `GET /health`
return `{"ok": true}` for health checks.

## Public registry (live) — read-only static host

**URL:** https://themythofsisyphusjayant.github.io/RED-MOON-/registry-static/

**Host:** GitHub Pages (static files, no server code running).
30 packages, all version 0.1.0, seeded from `packages/` on
21 Nov 2026. The static tree is generated by
`tools/make_static_registry.py` and lives in `registry-static/`
in this repo (`packages.json` + `packages/<name>/<version>/<file>.fg`).

**Clients** (no token needed — reads are public):

    qasida pkg list-static https://themythofsisyphusjayant.github.io/RED-MOON-/registry-static
    qasida pkg add-static https://themythofsisyphusjayant.github.io/RED-MOON-/registry-static checks@0.1.0

**Why static:** the dynamic server needs a host that runs a
persistent Python process with a writable disk. Evaluated
21 Nov 2026 — Vercel is serverless (no persistent process;
writes would need a Blob-store rewrite of the server, and the
connector's deploys have a 403 team-scope history); Render's
free tier has an ephemeral disk (published packages vanish on
restart) and needs a Render account; Fly.io needs an account
and a credit card; a VPS is paid. GitHub Pages needs no new
account, no payment, and the client already speaks the static
protocol (`add-static` / `list-static`).

**Honest limits of the public host:**

- `add-remote` does **not** work against static files. Its URL
  scheme (`GET /api/packages/<name>/<version>` returning JSON,
  and `GET /api/packages/<name>/<version>/<file>` returning
  text) needs one path to be both a file and a directory, which
  a static host cannot do. Verified 21 Nov 2026: `add-remote`
  against the static tree returns 404, and the filesystem
  itself refuses to create both. Use `add-static` for the
  public host; `add-remote` is for a dynamic server.
- `publish-remote` does **not** work against static files
  (there is no POST). Publishing to the public registry is via
  git — see "Republishing" below. `publish-remote` against a
  dynamic server with a token is verified (see below).

## Republishing the public registry

To add a package or publish a new version:

1. Add or update the package in `packages/` (bump `version`
   in its `forge.toml` for a new version).
2. Seed a local registry dir from `packages/`:

       export FORGE_REGISTRY=/tmp/regseed
       for d in packages/*/; do (cd "$d" && qasida pkg publish); done

3. Regenerate the static tree (this wipes `registry-static/`
   and rebuilds it from the seed):

       python3 tools/make_static_registry.py /tmp/regseed registry-static/

4. Push with `scripts/push_forge.py` (check no other
   `push_forge.py` is running first). GitHub Pages rebuilds
   in about a minute; verify with
   `qasida pkg list-static <url>` afterwards.

## Token rotation

The public static host has **no token** — reads are public and
there is nothing to rotate. The token (`FORGE_REGISTRY_TOKEN`)
applies only to a self-hosted dynamic server: it is read from
the environment, never stored in this repo. To rotate it, set
the new value on the host (Render/Fly/systemd env) and share
it with publishers out of band; the old token stops working
immediately. There is no token revocation list — the single
env var is the whole mechanism.

## Docker (any VPS with Docker)

    docker build -t forge-registry -f registry/Dockerfile .
    docker run -d -p 8765:8765 -e FORGE_REGISTRY_TOKEN=secret \
      -v forge-data:/data forge-registry

## Render (Blueprint, one click)

Dashboard -> New -> Blueprint, point it at this repo
(`registry/render.yaml`). Set `FORGE_REGISTRY_TOKEN` in the
dashboard when prompted; Render assigns `PORT` itself.

Warning: a free Render instance has an ephemeral disk, so
published packages vanish on restart/redeploy. For the real
public registry, attach a persistent disk (paid instance) or
use Fly / a VPS below.

## Fly.io (persistent volume)

From the repo root, in order:

    fly launch --no-deploy
    fly volumes create qasida_data --size 1 --region iad
    fly secrets set FORGE_REGISTRY_TOKEN=secret
    fly deploy --config registry/fly.toml --dockerfile registry/Dockerfile

The volume persists published packages across deploys. If `fly
launch` suggested a different app name, change the `app` line in
`registry/fly.toml` to match.

## VPS without Docker (systemd)

    # clone the repo to /opt/qasida (or edit WorkingDirectory)
    sudo mkdir -p /var/lib/qasida-registry
    sudo chown nobody:nogroup /var/lib/qasida-registry
    # optional token: FORGE_REGISTRY_TOKEN=secret in /etc/qasida-registry.env
    sudo cp registry/qasida-registry.service /etc/systemd/system/
    sudo systemctl daemon-reload && sudo systemctl enable --now qasida-registry

Put nginx/Caddy with HTTPS in front for public use — the server
itself is HTTP only, and the Bearer token must not travel over
plain HTTP on the public internet.

## Clients (dynamic server)

Once the server is up at `https://<your-host>` (or
`http://<your-host>:8765` for a local test):

    qasida pkg publish-remote https://<your-host> --token secret
    qasida pkg add-remote https://<your-host> checks@0.1.0
    qasida pkg list-remote https://<your-host>

`publish-remote` with a token is verified end to end against a
local server (21 Nov 2026): publish lands on disk, missing
token is rejected 401, republishing an existing version is
rejected 409, and `add-remote` from a clean consumer vendors
the package byte-identical.

## What is NOT provided here

A dynamic host. This repo gives you the server and the deploy
files, not a VPS, Render account, or domain. The public
registry above is the static GitHub Pages host; a dynamic
server (one that accepts `publish-remote`) still needs a host
you control — run the above on it, then share its URL.
